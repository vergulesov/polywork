# SALES RSS — утверждённый roadmap (09.10.2026)

Цель: не терять подходящие вакансии, оперативно находить лучшие предложения, не захламлять ручной просмотр. Источник — HH RSS, без HH API. Не изменять сборщик подработок polywork-ops.

## P0 — полнота сбора (в работе)

- [x] Отдельный изолированный сборщик и таймер каждые 30 минут
- [x] Трёхдневное окно RSS и дедупликация по HH ID
- [x] Не отбрасывать вакансии с неизвестным окладом: `NEEDS_REVIEW`
- [x] Сохранять RSS-описание вакансии в `SALES_RAW_V2` (N) и статус зарплаты (O)
- [x] Увеличить проверку RSS до 8 страниц/запрос/режим и выводить предупреждение при упоре в лимит
- [x] Выводить статистику отсечения по причинам
- [ ] На VPS применить, подтвердить успешный запуск и запись в Google Sheets
- [ ] Измерить полноту: сравнить новые HH ID с историческим RAW за 7–9 октября и вручную проверить пропуски
- [ ] При необходимости дополнить поисковые формулировки и глубину после анализа предупреждений
- [ ] Минимизировать необоснованные жёсткие отсечения по названию, графику и географии на основе реальных примеров

Важно: 8 страниц и 16 фраз не гарантируют полной выдачи HH. `REMOTE_SEARCH` — результат фильтра RSS, не юридическое подтверждение удалёнки. При `pagination_warnings` требуется дополнительная итерация по охвату.

## P1 — квалификация и список кандидатов

- [ ] Проверить полноту RSS-текстов на 30–50 реальных вакансиях
- [ ] Использовать GigaChat-анализ: работа, входящие/база, холодные, формат, оплата, продукт; отсутствующие данные — UNKNOWN
- [ ] Сверка с фактическими откликами/отказами из таблицы
- [ ] 70+ в SALES_CANDIDATES, ручные ✅/❌; ежедневная страховка для пограничных случаев
- [ ] Калибровка на размеченных пользователем примерах; пока RAW-only, без автоматического жёсткого отсева по баллам

## P2 — уведомления и скорость

- [ ] Telegram-оповещения по подтверждённо сильным находкам, 85+
- [ ] Измерять: публикация → сбор → уведомление → отклик
- [ ] При стабильной работе перейти с 30 на 15 минут (после проверки нагрузки/ошибок)
- [ ] Проверка актуальности, уведомления о сбоях сбора

### Готовность P0

Новые вакансии с неопределённой зарплатой сохраняются, у каждой записи есть RSS-описание, журнал показывает ошибки/обрезанную пагинацию и причину отсева, нет потери существующих листов и сервиса polywork-ops. При необходимости донастраиваются условия локальности и поисковые запросы.
