# Основная работа: вакансии B2B-продаж v2

Отдельный от PolyWork подработок сборщик: `sales_vacancies.py`.

## Безопасный запуск

На VPS после переключения на ветку:

```bash
cd /opt/polywork
git fetch origin
git switch feature/sales-vacancies-v2
/opt/polywork/.venv/bin/python -m py_compile sales_vacancies.py
/opt/polywork/.venv/bin/python sales_vacancies.py --days 7 --pages 2 --limit 50
```

По умолчанию **dry run**: показывает статистику и 20 примеров, **не пишет** ни в SQLite, ни в Google Sheets. Требуется доступ к api.hh.ru. `--limit` ограничивает число запросов полных карточек, а не число результатов поиска.

После просмотра dry run и проверки конфигурации (ТОЛЬКО ПОСЛЕ ЭТОГО):

```bash
export SPREADSHEET_ID='ID_ВАШЕЙ_ТАБЛИЦЫ'
export GOOGLE_APPLICATION_CREDENTIALS='/opt/polywork/google-service-account.json'
/opt/polywork/.venv/bin/python sales_vacancies.py --days 3 --pages 2 --write
```

При записи создаются **отдельные** листы `SALES_RAW_V2`, `SALES_CANDIDATES`, `SALES_APPLY`, исходные листы не меняются. В `SALES_CANDIDATES` в колонке **J** ставить ровно `✅` (одобрить) или `❌` (отклонить); при следующем запуске с `--write` одобренное появится в `SALES_APPLY`. Отклик отмечать вручную в колонке G листа `SALES_APPLY`. Лист не пересортировывается автоматически: ручное решение всегда привязано к HH ID.

## Ограничения v1

- Оценка по **эвристикам**, а не LLM: строго фиксированная шкала до 100. 70+ направляется на ручное решение, но точность требует калибровки.
- Неизвестная зарплата или нижняя граница ниже 80 тыс. ₽ **не проходят** в новый RAW. Вакансии с доходом 80–120 тыс. без опубликованного оклада будут пропущены. Это сознательно строгая стартовая настройка.
- Удалённый формат подтверждается HH `work_format` или `schedule=remote`. Доступность из Челябинска и офис рядом с домом **не проверяются автоматически**; местные вакансии требуют ручной проверки адреса.
- Глубина поиска ограничена `--pages` (по умолчанию 2 × 100 вакансий на запрос/режим); при большой выдаче возможны пропуски, особенно при давно отключённом сборщике.
- Старый `seen_hh` не трогается. Новые состояния лежат в `data/sales_v2.sqlite3`. Старый RAW **не импортируется автоматически**, для восстановления истории нужна отдельная миграция.
- Для запуска нужен `requests`, `gspread`; скрипт не регистрирует таймер и не включает Telegram самостоятельно.
- Сначала протестировать качество 30–50 рекомендаций, прежде чем планировать регулярный запуск. Не передавать токены и `google-service-account.json` в публичный GitHub.
