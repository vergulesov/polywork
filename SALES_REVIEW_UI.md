# Интерфейс ручного разбора 66 вакансий

Запускает отдельную локальную страницу «Вакансия N из 66» с ✅/❌/⏳, комментариями и сохранением в Google Sheets. Не трогает `sales-rss.service` и `polywork-ops`.

## Запуск на VPS

```bash
cd /opt/polywork
git pull --ff-only
.venv/bin/python -m py_compile sales_review_web.py
set -a; . ./sales-rss.env; set +a
.venv/bin/python -u sales_review_web.py
```

Держать терминал открытым при первом тесте. Сервис слушает **только** `127.0.0.1:8765`, в публичный Интернет не открыт.

На своём Windows-ПК открыть *второй* терминал SSH (подставить привычный адрес VPS):

```bash
ssh -L 8765:127.0.0.1:8765 root@АДРЕС_VPS
```

Затем на ПК открыть в браузере **http://127.0.0.1:8765**. В конце теста Ctrl+C в первом SSH-терминале остановит интерфейс; сборщик RSS продолжит работать.

## Что сохраняется

- `SALES_REVIEW` — новое отдельное поле учёта решений, HH ID, ✅/❌/⏳, комментарий, время, ссылка.
- `SALES_APPLY` — одобренные, без дублей HH ID. Отказ из APPLY удаляет только запись со статусом «Не откликался»; уже состоявшиеся отклики не стираются.
- `SALES_RAW_V2` — **не изменяется**.

Карточки фиксируют первоначально выбранные 66 HH ID, а данные названий/зарплат берут из `SALES_RAW_V2`. После перезагрузки решения сохраняются.

## Ограничения первого выпуска

RSS часто содержит только компанию, регион, зарплату, дату — **не** полную должностную инструкцию. В карточке выводится именно сохранённый RSS-текст и прямая ссылка на HH. Пока нет автозагрузки полного HH описания, вакансии **нельзя** уверенно квалифицировать по источнику клиентов, фиксированной ставке, KPI, графику или командировкам. «Предварительная оценка» — честные указатели на признаки названия, **не выдуманная ИИ-оценка**.

Для полноценной проверки сначала открой оригинал HH из карточки, затем выбери решение и оставь обоснование. Следующая итерация: сбор полного текста с разрешённого источника/ручная вставка, подробное резюме, оценка по требованиям.
